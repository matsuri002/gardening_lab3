# Pull Request 作成基準 (PR Standard)

このファイルは、Pull Request (PR) の説明文を作成する際の標準的なガイドラインを定義したものです。Issue で定義した「方向性」に対し、実際に「どのような実装を行ったのか」を具体的に記録することを目的としています。

---

## 1. 説明文の構成要素

AI が PR 説明文を生成する際は、必ず以下の要素を盛り込んでください。

### 概要 (Summary)
- **何を変更したか**: 最終的な成果の要約（1〜2文）。
- **なぜそうしたか**: 実装中に判断した技術的な選択理由や、当初の方向性から変更があった場合はその理由。

### 主な変更点 (Detailed Changes)
- **具体的な実施内容**: ソースコードの差分 (diff) と `CHANGELOG_featX.md` に基づき、実際に行った修正をリストアップする。
- **リファクタリングの詳細**: 分割したコンポーネント名や抽出したフック名などを具体的に明記する。
- **Co-location の適用状況**: 実装ファイルと仕様書がどのように配置されたかを記述する。

### 完了定義 (DoD) に基づく確認事項
- **Issue との同期**: Issue で定義した完了定義を転記し、実際の達成状況をチェックする。
- **未達成事項**: もし DoD の中で今回未達成だったものがあれば、その理由と今後の予定を記述する。

### 影響範囲
- 修正・追加された主要なファイルへのリンク。

---

## 2. AI 生成時の運用ルール

1. **ソースコードの確認**: 生成前に必ず `git diff` や `ls -R`、`CHANGELOG` を確認し、事実に基づいた記述を行うこと。
2. **コピー用マークダウン**: ユーザーがそのまま GitHub に貼り付けられるよう、**必ずマークダウン形式（コードブロック内）で出力する**こと。
3. **正確性の重視**: Issue の内容をなぞるのではなく、**「実際に書かれたコード」**を正として説明文を構成すること。

# CHANGELOG 管理ルール

プロジェクトの変更履歴を、開発ブランチごとに独立して管理し、透明性を高めるためのルールです。

## 1. ファイル構成

- **個別ファイル**: 各機能開発ブランチ（`feat/X`）ごとに `CHANGELOG_featX.md` を作成します。
- **格納場所**: すべての個別ファイルは本ディレクトリ（`changelogs/`）に格納します。

## 2. 記述形式

- **セクション分割**: 作業単位ごとに「コミットX」としてセクションを分けます。
- **構成要素**:
  - 推奨コミットメッセージ（gitmoji を含む）
  - 具体的な修正内容（箇条書き）
- **整合性**: 実際の Git コミットと CHANGELOG の記述が 1:1 で対応していることを推奨します。

## 3. 命名規則

`CHANGELOG_feat[番号].md`
例: `CHANGELOG_feat4.md`

## 4. テンプレート

```markdown
# Gardening Lab 3 - feat/[番号] 修正内容まとめ

[概要の記述]

## コミット履歴

### コミット[番号]: [作業名]

**推奨コミットメッセージ:**
\`\`\`text
[gitmoji] feat/[番号]: [概要]
\`\`\`

**修正内容:**

- [内容1]
- [内容2]
```
